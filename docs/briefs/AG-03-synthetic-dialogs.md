# AG-03. Синтетические диалоги для тестов краевых случаев

**Цель:** набор новых выдуманных чатов (не из DEV) в формате API организаторов с ожидаемыми ответами по критериям. Нужен для юнит-тестов фактов и для проверки, что оценщик не переобучился на DEV.

**Контекст:** `docs/task/brief.md` раздел 3 (формат данных), `docs/checklist.md` (критерии и памятка), `docs/research/01-data-overview.md` (трудные случаи по критериям). Посмотри на структуру чатов `p1-*` в `DEV_readable.md`, но не копируй их тексты и сюжеты.

**Сделать:**
1. `tests/fixtures/synthetic/dialogs.json` — объект как ответ API: `{"isSuccess": true, "error": "", "data": {"dataset_group_id": "SYNTH", "total_records": N, "records": [...]}}`. 24 чата: RU 10, KZ 7, EN 7, плюс 2 звонка из п. 3b; `conversation_id` вида `s-ru-001`; `channel: "agent chat"`; время `MM:SS`; роли `client`, `operator`, `bot`, `system`.
2. Покрыть случаи (каждый минимум 2 раза, на разных языках): оператор не поздоровался или не представился; представился во второй реплике; ответил не на языке клиента; раскрыл данные счёта без идентификации; общий вопрос без идентификации (03 = N/A); клиент ушёл до запроса (04 = N/A); обрыв связи (07 = N/A); оператор закрыл чат без прощания (07 = Нет); пауза оператора больше 3 минут без предупреждения; клиент переспрашивает из-за непонятного ответа (06 = 4); недовольный клиент без реакции на проблему (05 = Нет); предложение платной услуги лично (08 = Да); оскорбление (08 = Да); идеальный диалог.
3. Хотя бы 4 диалога **без** бота и эскалации (оператор отвечает сразу) и 2 с непривычными системными сообщениями — контроль может отличаться от DEV.
3a. Случаи с нехваткой данных — модель должна сказать «данных недостаточно», а не догадываться: только бот, оператор так и не подключился (2); обрыв сразу после первой реплики оператора (2); клиент ссылается на прошлый разговор или документ, которого в чате нет (2). В `expected.json` у таких критериев поле `insufficient: true`.
3b. Два синтетических звонка (`channel: "voice call"`, `conversation_id` вида `s-call-001`, время ISO 8601 как в формате API, `audio_url: null`) с типичными ошибками распознавания речи, повторами и словами-паразитами: оператор работает хорошо, и баллы за это снижаться не должны. Реальные звонки `p4-*` не открывать и не копировать.
4. `tests/fixtures/synthetic/expected.json` — ожидаемые ответы по формату `data/gold/README.md` + поле `case` с описанием, что проверяет диалог.

**Не трогать:** всё, кроме `tests/fixtures/synthetic/`.
**Готово, когда:** JSON валиден, 24 чата и 2 звонка, каждый случай из пп. 2, 3a, 3b покрыт, у каждого диалога есть ожидаемые ответы.
**Ветка:** `test/synthetic-dialogs`. Коммит: `test(data): synthetic edge-case dialogs with expected labels`.
