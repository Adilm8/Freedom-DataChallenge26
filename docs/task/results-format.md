# Формат сдачи результатов (приложение к гайду, формат JSON 1.0)

Текстовая копия приложения организаторов «Как сдать результаты» (получено 2026-11-07). Ссылок с подписью в нём нет. Реализация — `backend/app/services/results_export.py`, `scripts/export_results.py`.

## Что сдаём

```
results/
  dev/results.json     # DEV: 60 чатов и 5 звонков
  prod/results.json    # 10 контрольных чатов
```

- Через 23 часа после старта приходит контрольный набор (10 чатов). До стоп-кода (24 часа) нужно получить данные через выданный API, оценить, проверить JSON, сделать commit **и push**. Способ получения контроля сообщат за час до стоп-кода.
- Оба файла должны лежать в **открытом** репозитории по ссылке, **заранее переданной организаторам**. Локальный файл или commit без push не засчитываются.
- Исходные `conversation_id` из API сохраняем без изменений. Одна запись на диалог, без пропусков и повторов. В prod ровно 10 записей, включая ошибки.

## Структура

```json
{
  "schema_version": "1.0",
  "team_name": "Название команды",
  "model": {"mode": "local | external_api | hybrid", "name": "фактическая модель (несколько — через запятую)"},
  "results": [
    {
      "conversation_id": "исходный ID",
      "status": "ok",
      "criteria": [
        {"criterion_id": "contact", "value": true, "rationale": "кратко", "evidence_turns": [4]}
      ],
      "score": {"final_score": 85.38, "critical_flag": false}
    },
    {"conversation_id": "…", "status": "error", "criteria": [], "score": null, "error": "причина"}
  ]
}
```

| `criterion_id` | Критерий (наш ключ) | `value` | Вес |
|---|---|---|---|
| `contact` | Установление контакта (01) | `true` / `false` | 10 |
| `discovery` | Выявление потребности (02) | `true` / `false` / `null` | 15 |
| `identification` | Идентификация (03) | `true` / `false` / `null` | 20 |
| `consultation` | Корректность и полнота (04) | `0, 5, 10, 15, 20` / `null` | 20 |
| `empathy` | Эмпатия (05) | `true` / `false` | 15 |
| `dialogue` | Ведение, скорость, грамотность (06) | `0, 4, 7, 10` | 15 |
| `closure` | Завершение (07) | `true` / `false` / `null` | 5 |
| `critical` | Грубые ошибки (08) | `true` / `false` | — |

## Правила заполнения

- `true` = «Да», `false` = «Нет», `null` = N/A. Число — ступень шкалы до учёта веса (`dialogue = 7` — это 7 из 10 при весе 15).
- При `status: "ok"` нужны все 8 критериев, каждый ровно один раз. Названия полей, коды критериев и типы значений не менять.
- `rationale` — краткое объяснение. `evidence_turns` — номера подтверждающих реплик **с 1 по исходному массиву транскрипта**, включая клиента, бота и события (у нас `msg_id = m<idx>` с нуля, в файл пишем `idx + 1`).
- `final_score` — итог 0–100, два знака. N/A исключается, вес перераспределяется пропорционально. N/A — не ноль и не ошибка.
- `critical_flag` совпадает с `value` критерия `critical` и **не обнуляет итог** (у нас `critical_policy: flag`).
- Не удалось оценить: `status: "error"`, `criteria: []`, `score: null`, причина в `error`. Не скрывать и не подменять нулём.
- Перед push: UTF-8, без комментариев и лишних запятых, ID точно как в API.

Пример организаторов (02 и 03 — N/A, 04 = 15, 06 = 7, остальное «Да», 08 «Нет») даёт 85.38 и по нашей формуле (`tests/test_results_export.py`).
