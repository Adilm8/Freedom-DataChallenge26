# Задание: CQA Hackathon (Freedom Broker)

Сжатая текстовая копия гайда организаторов (`CQA_Hackathon_Student_Guide_v3`). Сам PDF в репозиторий не кладём: в нём подписанная ссылка на API.

## 1. Задача

Прототип Conversation Quality Analytics за 24 часа.

- **Настройка и автоматическая оценка.** Пользователь настраивает чек-лист, загружает диалоги и запускает оценку работы оператора. Система показывает баллы, объяснения и реплики, на которых основан вывод.
- **Результаты, апелляция и пересмотр.** Пользователь просматривает оценку и оспаривает критерий. Проверяющий изучает доказательства, подтверждает или меняет оценку и сохраняет финальный результат.

Данные: DEV — 65 диалогов (60 синтетических чатов + 5 реальных звонков), языки 35 RU / 15 KZ / 15 EN. Для звонков есть транскрипт и ссылка на запись.

Контроль: через 23 часа организаторы откроют дополнительные транскрипты. Отдельно предложат заменить один критерий — сохранить новый чек-лист через интерфейс и применить его к выданным диалогам.

Формат: интерфейс на HTML, CSS и JavaScript, структура пригодна для адаптации как HTML-компонент Dynamics 365. Модель, сервер и хранение — на выбор команды. Регистрация и вход не нужны.

## 2. Функции

**Контур 1 · Оценка**

1. **Создать чек-лист.** Добавлять и менять критерии, формулировки, вес, тип ответа и доступность N/A. Для числового критерия — шкала. Новый критерий применяется через настройки. Конфигурация сохраняется.
2. **Оценить выбранный диалог.** Загрузить транскрипт, выбрать чек-лист, запустить оценку оператора. RU, KZ, EN. Реплики бота и системные события — контекст.
3. **Показать результат.** По каждому критерию: ответ, баллы, вес, объяснение, реплика-доказательство. Пропущенное действие — указать проверенный участок разговора. N/A — объяснить причину. Итог и результаты секций, если заданы.

Вес и итог: шкальные оценки пересчитываются с учётом веса; при N/A вес перераспределяется; грубая ошибка отмечается отдельно; правила и округление — из чек-листа (`docs/checklist.md`).

**Контур 2 · Работа с результатом**

4. **Карточка.** Из списка — к транскрипту и результату. Ссылка в обосновании ведёт к нужному сообщению или фрагменту звонка. Для записи — прослушивание или переход к плееру.
5. **Апелляция.** Выбрать критерий, добавить комментарий, сохранить обращение. Проверяющий видит спорную оценку, комментарий и фрагмент диалога.
6. **Решение.** Проверяющий подтверждает или меняет оценку и указывает причину. Итог пересчитывается. В карточке видны исходная оценка, решение и финальный результат.

## 3. Данные (временный API)

`GET <URL>&group_id=DEV` (URL — в `.env`, `ORGANIZER_API_URL`). Для контроля организаторы сообщат другой `group_id`.

```json
{ "error": "", "isSuccess": true, "data": {
  "dataset_group_id": "DEV", "total_records": 65,
  "records": [{
    "conversation_id": "p1-ru-001",
    "channel": "agent chat", "language": "RU",
    "transcript": [{"timestamp": "00:02", "speaker": "operator", "text": "Здравствуйте!"}],
    "audio_url": null
  }]
} }
```

- `channel`: `agent chat` или `voice call`; `language`: RU, KZ, EN.
- `transcript` — массив реплик `timestamp`, `speaker`, `text`. Роли: `client`, `operator`, `bot`, `system`. Исходные метки времени сохранять.
- Время: чаты — `MM:SS`, звонки — ISO 8601 с часовым поясом. `audio_url` пустой у чатов, ссылка у звонков.

## 4. Сдача

- **Час 23:** контрольные транскрипты — запустить обработку заранее, чтобы результаты были готовы к выступлению.
- **Час 24:** стоп-код, последний коммит в открытом Git-репозитории (ссылку отправить организаторам заранее), README с шагами запуска. Обработку данных и изменение чек-листа через UI можно делать на зафиксированной версии.

**Защита — максимум 5 минут:**

1. 1 мин — интерфейс и выбранный диалог.
2. 2 мин — оценка, обоснование, переход к реплике, пример N/A, итоговый балл.
3. 1 мин — апелляция, решение проверяющего, новый итог.
4. 1 мин — изменение критерия и применение чек-листа.

**FAQ:**

- ИИ — любой: локальная модель, бесплатный или платный API. Для платной указать название и примерную стоимость одной оценки с учётом всех вызовов.
- Распознавать речь не нужно, транскрипты выданы. Для оценки дикции и интонации нужен звук.
- CORS — запрашивать данные через сервер или локальный адаптер.
- Авторизация не нужна. Подачу апелляции и её проверку показать как отдельные действия в интерфейсе.
