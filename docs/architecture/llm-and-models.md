## 1. Провайдеры

Один интерфейс, одна реализация на OpenAI-совместимом API (SDK `openai`), разные `base_url`:

| Провайдер | Назначение | Ограничения |
|---|---|---|
| `openrouter` | eval, финальные и контрольные прогоны; доступ к Claude, GPT, Gemini, открытым моделям | платный, небольшой бюджет ([Q-03](../spec/open-questions.md)) |
| `gemini` (AI Studio free) | черновая gold-разметка и отладка на синтетических чатах | лимиты RPM/RPD; данные могут использоваться Google → **звонки `voice call` туда не отправляются**, блок в коде (FR-EVAL-10) |
| `ollama` | локальная модель для «разнообразия подходов» | только если останется время ([ADR-012](../decisions/ADR-012-local-model-deferred.md)) |

```python
class LLMProvider(Protocol):
    name: str
    def complete(self, messages: list[dict], *, model: str, json_schema: dict | None,
                 max_tokens: int, temperature: float | None, timeout_s: float) -> LLMResult: ...

@dataclass
class LLMResult:
    text: str; parsed: dict | None; finish_reason: str
    provider: str; model: str            # фактическая модель из ответа
    tokens_in: int; tokens_out: int; cached_tokens: int
    cost_usd: float | None; latency_ms: int; raw: dict
```

Детали:

- **Строгий JSON.** OpenRouter: `response_format: {type: "json_schema", json_schema: {strict: true, schema}}` + `provider: {require_parameters: true}`, чтобы запрос не ушёл к провайдеру без поддержки схемы. Нет поддержки → `{"type": "json_object"}` + Pydantic + ретрай. Какие параметры модель принимает — `supported_parameters` из `GET /api/v1/models`, кешируем при старте.
- **Температура.** `0`, только если модель её принимает; иначе параметр не передаём. Фактические параметры пишем в `llm_call.request`.
- **Стоимость.** Берём из ответа OpenRouter (`usage`); если провайдер её не вернул — считаем по таблице цен `providers/pricing.py` (цены из `GET /api/v1/models`). Gemini free = 0, но токены пишем.
- **Сетевые ошибки.** 429 и 5xx → backoff 2 / 4 / 8 с, максимум 3 попытки; это отдельно от ретрая валидации.
- **Параллельность.** Семафор на провайдера: OpenRouter 8, Gemini free 2 (настройка `.env`).
- **Кеш префикса.** Порядок частей промпта (правила → факты → транскрипт → критерий) даёт кеш у провайдеров с автоматическим кешированием. Кеш ответов LLM в демо выключен (NFR-05).

## 2. Роли моделей

| Роль | Чем занята | Модель (до bake-off) | Переменная |
|---|---|---|---|
| `draft` | черновая gold-разметка, отладка промптов | сильная модель через OpenRouter для gold; Gemini free для отладки на чатах | `DRAFT_MODEL` |
| `eval` | итерации `run_eval` | средняя по цене модель-кандидат | `OPENROUTER_MODEL` |
| `final` | финальный прогон DEV, контроль, демо | победитель bake-off | `OPENROUTER_MODEL` (переключаем перед финалом) |

Gold-черновик и судья должны быть разными моделями, где это возможно: иначе Лида будет проверять разметку той же модели, которую мы потом меряем, и согласие завысится.

## 3. Bake-off (выбор модели)

1. **Смоук** (`scripts/model_smoke.py`): 3–5 кандидатов (сильная, средняя, дешёвая/открытая) на 3 диалогах RU / KZ / EN — поддержка JSON-схемы, адекватность на KZ, задержка, цена. Точные id — из текущего списка OpenRouter (`--list`), не из памяти.
2. **Прогон** на gold-dev: 2–3 лучших × стратегия `per_criterion`, лучший ещё и с `single`.
3. **Выбор**: среднее согласие по критериям → recall флага 08 → согласие на KZ → MAE итога → цена одной оценки.
4. Победитель и цифры — в ADR, цена одной оценки — в README.

## 4. Бюджет (заполнить после ответа на Q-03)

| Статья | Прогонов | Оценка |
|---|---|---|
| Смоук моделей | 1 | копейки |
| Gold-черновик (сильная модель, 65 диалогов, `single`) | 1–2 | ~ |
| Bake-off на gold-dev | 3–5 | ~ |
| Итерации промпта на `eval`-модели | 10–15 | ~ |
| Финальный прогон DEV + контроль + демо | 3–4 | ~ |

Правило: прогон на дорогой модели — только на gold-подмножестве, полный DEV — только финальной моделью.
