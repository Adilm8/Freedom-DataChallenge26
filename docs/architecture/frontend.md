## 2. Карточка подробно

- **Транскрипт:** каждая реплика — блок с `id="msg-m9"`, ролью (цвет), временем и текстом. Бот и system приглушены, `internal`-реплики звонка подписаны «внутренний разговор». Факты (подсказки кода) — значки на полях у нужных реплик.
- **Результат:** по секциям; строка критерия = код, название, ответ (цветной бейдж), «баллы / вес», вклад, обоснование, чипы доказательств `m9`. Клик по чипу → прокрутка к реплике, подсветка; у `checked_range` — подсветка диапазона. У N/A — причина. У «требует проверки» — значок с текстом предупреждений.
- **Апелляция:** у каждого критерия кнопка «Оспорить» (режим аналитика) → комментарий → сохранить. Если решение есть — видно «AI: Нет → Проверяющий: Да, причина: …», итог показывает «AI 82.50 → финальный 87.50».
- **Плеер (звонок):** `<audio>` с `audio_url`; клик по реплике или доказательству → `currentTime = audio_offset_sec + поправка`. Если запись не грузится в браузере — ссылка «открыть запись» и прокси через бэкенд (допущение A-5).
- **Таймлайн (FR-UX-01):** полоса над транскриптом — бот, эскалация, первый ответ оператора с задержкой, идентификация, ожидания, завершение; метки доказательств; клик → реплика или секунда записи.
- **Уверенность и рекомендация:** у критерия значок уверенности (низкая — заметно), у «Нет» и неполной ступени — подсказка оператору «что можно было сделать» (FR-EVAL-16, 18).
- **Метки на репликах (FR-UX-04):** у реплики-доказательства видны коды критериев, которые на неё ссылаются.
- **Обзор диалога:** резюме, тема и «вопрос решён / нет / неясно» над результатом (FR-EVAL-19).
- **«Оценить повторно»:** запускает ту же конфигурацию заново и показывает расхождения с прошлой оценкой (FR-EVAL-20, FR-CARD-06). Переиспользованные ответы подписаны «из оценки #…» (FR-CHK-10).
- **Метаданные:** модель, стратегия, версия чек-листа и промпта, токены, стоимость, время; «Сырой ответ» открывает JSON вызовов LLM.

## 2a. Качество интерфейса (NFR-12)

Лида: «интерфейс в любом случае должен быть очень хорошим». Поэтому:

- Единая палитра, отступы и шрифты — CSS-переменные в `css/cqa.css`; один стиль бейджей ответов (Да / Нет / N/A / ступень / флаг) во всех экранах.
- У каждого экрана есть состояния загрузки, пустого списка и ошибки с понятным текстом.
- Режим демо (`?demo=1` или кнопка): крупнее шрифт и бейджи для проектора.
- Без горизонтальной прокрутки на 1280 px; транскрипт и результат прокручиваются независимо.
- Частые действия доступны с клавиатуры (экран gold, переход между диалогами).
- Дизайн-система с первого шага фронта (шаг 5 плана), дизайн-проход (шаг 26) и проход по удобству с Лидой (шаг 27, FR-UX-07): Лида без подсказок проходит весь процесс, все трения исправляем.
- Пустые экраны с подсказкой следующего действия («Импортируйте набор», «Запустите оценку»).
- Если есть запас (C): тёмная тема на тех же переменных, печатная версия карточки, горячие клавиши с подсказкой по `?`.

## 3. Контракт компонента (под Dynamics 365)

Каждый компонент — модуль `js/components/<name>.js`:

```js
export function mount(el, params) {      // el — любой <div>, params — объект из query-строки
  // рисует себя внутри el, ничего не трогает снаружи
  return { update(newParams) {}, unmount() {} };
}
```

- Параметры только из `params` (а те — из query-строки или из `data`-параметра web resource D365). Глобального состояния нет, кроме `js/api.js`.
- `js/api.js` — единственное место с `fetch`. Базовый URL берётся из `?api=` или `window.CQA_API_BASE`, по умолчанию тот же origin. Для D365 бэкенд просто будет внешним адресом.
- Стили — `css/cqa.css`, все классы с префиксом `cqa-`, цвета через CSS-переменные на `.cqa-root`. Никаких стилей на `body` и глобальных тегах, кроме оболочки `index.html`.
- `pages/<name>.html` — тонкие страницы с одним `<div>` и одним `mount()`: так компонент можно открыть отдельно, как будущий HTML web resource.
- Компоненты общаются через события DOM на своём корне (`cqa:navigate`, `cqa:evidence-click`), а не через прямые вызовы друг друга.

## 4. Порядок работы, чтобы не ждать бэкенд

1. Фикстуры `frontend/fixtures/*.json` по `CONTRACTS.md` (список, карточка с результатом, чек-лист, апелляция).
2. `api.js` умеет режим `?mock=1` — читает фикстуры. Фронт делается параллельно с бэкендом.
3. Когда эндпоинт готов, режим `mock` для него просто не используется. Фикстуры остаются для тестов и вёрстки.
