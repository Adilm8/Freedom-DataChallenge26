# Документация проекта: карта и правила изменений

> Статус: действует · Обновлено: 2026-11-07 · Владелец: Claude · Утверждает: Лида

## Как менять документы

1. **ID не перенумеровываем.** `FR-EVAL-03`, `NFR-02`, `ADR-004`, `Q-05` живут до конца проекта. Ненужное требование помечаем `~~зачёркнуто~~ (причина, дата)`, а не удаляем. На ID ссылаются тесты, коммиты и брифы подагентам.
2. **Требование поменялось** → правим `spec/requirements.md` → если это выбор между вариантами, пишем или обновляем ADR → если затронуты схемы или API, обновляем `CONTRACTS.md` и поднимаем его версию → строка в `PROGRESS.md`.
3. **Решение поменялось** → старый ADR получает статус «Заменено ADR-0NN», новый ADR ссылается на старый. Историю не стираем: жюри смотрит на «качество процесса», а нам самим через 10 часов нужно помнить, почему так.
4. **Вопрос закрыт** → в `spec/open-questions.md` ставим «Решено: …» и ссылку на ADR. Если ответа нет к дедлайну вопроса, действует вариант по умолчанию, указанный там же.
5. **Статусы документа:** `черновик` → `согласовано` (Лида посмотрела) → `заморожено` (меняем только с записью в журнал внизу файла).
6. В конце каждого файла короткий журнал изменений: дата, что, почему.

## Ссылки на требования из кода

В тестах и докстрингах указываем ID: `# FR-SCORE-04: N/A перераспределяет вес`. Так видно, что сломается при изменении требования, и подагенту проще найти нужное место.
