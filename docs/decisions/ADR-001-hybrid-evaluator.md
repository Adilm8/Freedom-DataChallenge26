# ADR-001: Гибридный оценщик — факты кодом, суждения LLM, проверка и баллы кодом

- Статус: **Принято**
- Дата: 2026-11-07 · Кто решил: Лида (вариант 3 из `research/01`)
- Связано: FR-EVAL-03…07, FR-SCORE-*, NFR-01, NFR-05; `research/02` (Cresta, Contact Lens)

## Контекст
Главный критерий — точность против эталона. Часть сигналов лежит в данных (системные события, время, первая реплика оператора), и LLM их «додумывает» хуже кода. Остальное — смысловые суждения, где нужна модель. Жюри смотрит и на честность процесса.

## Решение
Конвейер `normalize → facts → judge (LLM) → validator → guards → scoring`. Код вычисляет факты и передаёт их модели как подсказки; LLM выбирает ответ из разрешённых и цитирует реплики; код проверяет ответ и цитаты и считает баллы. Правила-страховки для критериев (01, 03, 07) лежат в данных чек-листа и по умолчанию только помечают противоречие.

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| Только LLM, один вызов | быстро сделать, дёшево | «додумывает» проверку личности и события, нет контроля цитат |
| Только правила | детерминированно | не работает для 02, 04, 05, 06 и нового критерия на защите |
| **Гибрид** | точность + объяснимость + контроль | больше кода (факты, валидатор) |

## Последствия
Нужны тесты на факты и валидатор. Замена критерия через UI работает, потому что факты общие, а правила — в данных.

## Как пересмотреть
Если eval покажет, что для какого-то критерия правило точнее модели, — включаем у него `override` (данные, не код). Если факты мешают (модель слепо им следует) — убираем их из промпта для этого критерия.
