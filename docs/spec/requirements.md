# ТЗ: прототип CQA для Freedom Broker

> Статус: черновик v0.3 · Обновлено: 2026-11-07 · Владелец: Claude · Утверждает: Лида
> Источники: `docs/task/brief.md`, `docs/task/selection_criteria.md`, `docs/task/organizer-message-2026-11-07.md` (уточнение организаторов об оценке), `docs/checklist.md` (PDF чек-листа — источник истины по правилам оценки), `docs/research/01-*.md`, `02-*.md`.

## 1. Цель и критерии успеха

Сделать за оставшиеся ~20 часов прототип, который по настраиваемому чек-листу оценивает работу оператора в чате или звонке, объясняет каждую оценку репликой-доказательством и поддерживает апелляцию с пересчётом итога.

Как нас оценивают и что из этого следует:

| Критерий жюри | Вес для нас | Что это значит для решения |
|---|---|---|
| Точность против Ground Truth на 10 новых диалогах | главный | Организаторы уточнили: смотрят на близость и адекватность оценки в целом, а не на совпадение каждой цифры, и просят не угадывать их внутреннюю методику. Оценщик, eval против gold, выбор модели по метрике (NFR-01), но цикл подгонки короткий. |
| Обоснованность и воспроизводимость | высокий | Каждый ответ опирается на реплику или факт; при нехватке данных система так и говорит, а не придумывает; повторная оценка даёт тот же результат (FR-EVAL-16, 20, NFR-13, 14). |
| Функциональность и уникальные возможности | высокий | Полный процесс двух контуров + заметные доп. функции: аналитика по группе, таймлайн диалога, рекомендации оператору, очередь «требует проверки», мгновенный пересчёт при смене весов (раздел 5.10, FR-CHK-10). |
| Удобство | высокий | Удобный и приятный интерфейс: весь процесс от импорта до апелляции проходится без подсказок (NFR-12, FR-UX-07). |
| Корректность процесса | высокий | Только реальные вызовы LLM, видно модель, токены, стоимость и сырой ответ; замена критерия реально меняет оценку; новый диалог можно вставить и оценить на глазах у жюри (FR-DATA-07). |
| Технический подход и разнообразие | средний | Гибрид «код + LLM», проверка цитат кодом, выбор провайдера, сравнение моделей; локальная модель — опционально. |

Уточнение организаторов (2026-11-07) и что из него следует — `docs/task/organizer-message-2026-11-07.md`.

## 2. Рамки

**Входит:** импорт наборов по `group_id`, чек-лист как редактируемая версионируемая конфигурация, автооценка RU/KZ/EN (чаты и звонки), карточка с доказательствами и плеером, апелляция и решение проверяющего, пересчёт итога, экспорт результатов, eval против gold, аналитика по группе и дополнительные возможности из раздела 5.10, README.

**Не входит:** авторизация и роли с правами (только переключатель режима), распознавание речи, оценка интонации по звуку, многопользовательская работа, деплой в облако и в Dynamics 365 (только готовность структуры), fine-tuning, полноценный RAG с поиском (справка о продуктах маленькая и подставляется целиком, FR-EVAL-14).

## 3. Пользователи

Авторизации нет. Режим переключается в шапке интерфейса, чтобы подачу апелляции и её проверку показать как отдельные действия (требование FAQ).

| Режим | Что делает |
|---|---|
| Аналитик качества | импортирует наборы, запускает оценку, смотрит результаты, подаёт апелляцию |
| Проверяющий | разбирает очередь апелляций, подтверждает или меняет оценку с причиной |
| Настройка (любой режим) | редактирует чек-лист, сохраняет новую версию, применяет её к диалогам |

## 4. Термины

| Термин | Значение |
|---|---|
| Диалог | запись набора: `conversation_id`, канал, язык, транскрипт, `audio_url` |
| Реплика, `msg_id` | элемент транскрипта; `m0…mN` по исходному порядку, стабилен для ссылок |
| Чек-лист, версия | набор критериев с настройками; каждая сохранённая версия неизменяема |
| Критерий | вопрос о работе оператора: тип (`binary` / `scale` / `flag`), вес, N/A, шкала, инструкции |
| Ответ | `yes` / `no` / `na` для бинарных и флагов, ступень шкалы или `na` для шкал |
| Факты | то, что код вычисляет из данных до LLM: первая реплика оператора, задержки, системные события и т. п. |
| Оценка AI | результат конвейера; не перезаписывается |
| Финальная оценка | AI-оценка с применёнными решениями по апелляциям |
| Прогон | запуск оценки набора диалогов одной версией чек-листа и одной моделью |
| Gold | эталонная разметка DEV, которую проверяет Лида; только для eval, не для промпта |

## 5. Функциональные требования

Приоритет: **M** — без этого не сдаём; **S** — сильно влияет на оценку жюри; **C** — если останется время.

### 5.3 Оценка — EVAL

| ID | Требование | Пр. | Готово, когда |
|---|---|---|---|
| FR-EVAL-01 | Оценка выбранного диалога или набора по выбранной версии; асинхронно, с прогрессом | M | 10 диалогов запускаются одной кнопкой, прогресс обновляется |
| FR-EVAL-02 | Оценивается только оператор; `bot` и `system` — контекст | M | В промпте это правило есть; в gold-кейсах с ошибкой бота оператор не штрафуется |
| FR-EVAL-03 | По каждому критерию: ответ из разрешённых, обоснование, доказательства (`msg_id` + цитата). «Нет» — участок, где действие ожидалось (`checked_range`). N/A — причина | M | Схема ответа это гарантирует, валидатор проверяет |
| FR-EVAL-04 | Код проверяет ответ, `msg_id` и цитаты. Ошибка → один повтор с описанием ошибки → если снова ошибка, результат помечен «требует проверки» | M | Тест валидатора на подложенной выдуманной цитате |
| FR-EVAL-05 | Баллы и итог считает код | M | Модель цифр не возвращает; см. FR-SCORE |
| FR-EVAL-06 | Каждая оценка — реальный вызов LLM. Сохраняются провайдер, модель, версия промпта, версия чек-листа, токены, стоимость, задержка, сырой ответ | M | В карточке можно открыть сырой ответ и стоимость |
| FR-EVAL-07 | Слой фактов: код вычисляет первую реплику оператора и её язык, задержки, системные события, лексические подсказки и передаёт модели | S | Факты видны в промпте и в UI |
| FR-EVAL-08 | Стратегия вызовов (`single` / `grouped` / `per_criterion`) и модель задаются конфигом и при запуске, без правки кода | S | `run_eval.py --strategy … --model …` работает |
| FR-EVAL-09 | Обоснования на одном языке формы (RU по умолчанию, настройка чек-листа), цитаты — в языке оригинала | S | KZ- и EN-диалоги получают русские обоснования с оригинальными цитатами |
| FR-EVAL-10 | Звонки (`voice call`) не уходят бесплатному Gemini — блок в коде провайдера | S | Попытка даёт понятную ошибку, а не вызов |
| FR-EVAL-11 | Самосогласованность для шкал: N прогонов и медиана | C | Включается флагом, eval показывает эффект |
| FR-EVAL-12 | Правила-страховки из конфига критерия: при противоречии фактам — пометка или замена ответа | C | Включается в данных чек-листа, не в коде |
| FR-EVAL-13 | Локальная модель (Ollama) как ещё один провайдер — только если останется время | C | Тот же конвейер с `LLM_PROVIDER=ollama` |
| FR-EVAL-15 | Язык обоснований на выбор: русский (по умолчанию), язык диалога или английский — настройка чек-листа и выбор при запуске. Отмечено Лидой на будущее | C | Тот же диалог оценивается с `output_language` = `kz` / `en` |
| FR-EVAL-14 | Справка о продуктах Freedom Broker (`data/knowledge/`) подключается к критерию полем `context_refs` в чек-листе; по умолчанию — к 04 | S | eval по 04 с справкой и без неё; оставляем, если не хуже |
| FR-EVAL-16 | Не придумывать: каждое утверждение обоснования опирается на реплику (`msg_id`) или факт кода. У критерия есть уверенность `high` / `medium` / `low`. Если данных не хватает (обрыв, нет реплик оператора, неразборчивый фрагмент звонка, утверждение, которое по тексту не проверить), модель прямо это пишет, ставит `low` и отвечает по правилу чек-листа (N/A, если разрешён); результат получает пометку «требует проверки» | M | Синтетика: обрыв до ответа, только бот, непроверяемое утверждение — без выдуманных фактов, с пометкой |
| FR-EVAL-17 | Звонки: учёт устной речи. Оговорки, повторы, слова-паразиты, ошибки распознавания и перекрытия реплик не считаются ошибкой оператора; удержание и паузы оцениваются по фактам сегментов; сверка цитат мягче, чем у чатов | M | Синтетический звонок с ошибками распознавания не теряет баллы за «грамотность» |
| FR-EVAL-18 | Рекомендация оператору: для каждого критерия без полного балла — одна короткая подсказка, что можно было сделать иначе (поле `advice` в том же вызове) | S | У «Нет» и неполной ступени в карточке есть подсказка |
| FR-EVAL-19 | Обзор диалога: краткое резюме, тема обращения, решён ли вопрос (`yes` / `no` / `unclear`) — поле `overview` в первом вызове оценки; на баллы не влияет | S | Видно в карточке и в аналитике |
| FR-EVAL-20 | Воспроизводимость: оценка хранит всё для повтора (версия чек-листа, модель, стратегия, версия промпта, параметры вызова); `temperature: 0` и `seed`, где модель их принимает; кнопка «Оценить повторно» и сравнение с прошлым результатом | M | Повтор с тем же конфигом укладывается в NFR-14 |

### 5.4 Расчёт — SCORE

Правила — `docs/checklist.md`, «Порядок расчёта». Уточнения, принятые нами, — [ADR-006](../decisions/ADR-006-scoring-rules.md).

| ID | Требование | Пр. | Готово, когда |
|---|---|---|---|
| FR-SCORE-01 | «Да» = полный вес, «Нет» = 0 | M | Юнит-тест |
| FR-SCORE-02 | Шкала: `вес × ступень / максимальная ступень` | M | Юнит-тест: 06 = 7 → 10.5 |
| FR-SCORE-03 | Флаг (08) баллов не даёт и не входит в вес; отмечается отдельно | M | Юнит-тест |
| FR-SCORE-04 | N/A исключает критерий; итог = сумма баллов / применимый вес × 100 | M | Пример из чек-листа даёт **94.38** |
| FR-SCORE-05 | Округление итога до 2 знаков, половина — вверх | M | Юнит-тест на `x.xx5` |
| FR-SCORE-06 | Нет применимых критериев с весом → итог не рассчитывается (`null`) | M | Юнит-тест |
| FR-SCORE-07 | Итоги по секциям: баллы, применимый вес, процент | S | Видно в карточке |
| FR-SCORE-08 | Политика грубой ошибки задаётся в настройках чек-листа: `flag` (по умолчанию, как в PDF) или `zero_total` | C | Переключение меняет итог в тесте |

## 6. Нефункциональные требования

| ID | Требование | Цель |
|---|---|---|
| NFR-01 | Близость к эталону на отложенной части gold (организаторы смотрят на близость и адекватность, а не на совпадение каждой цифры) | итог: MAE ≤ 5, в пределах ± 10 баллов ≥ 90% диалогов; согласие ≥ 80% по каждому критерию, в среднем ≥ 90%; шкалы в пределах ± 1 ступени ≥ 95%; флаг 08 — recall 100% |
| NFR-02 | Скорость | чат ≤ 30 с; 10 диалогов ≤ 5 мин |
| NFR-03 | Стоимость | ориентир ≤ $0.05 за чат на финальной модели; уточняется после bake-off |
| NFR-04 | Надёжность | сбой вызова не валит прогон: ретраи с backoff, частичный результат с пометкой |
| NFR-05 | Честность процесса | никаких заготовленных результатов и кешей ответов LLM в демо; никаких цитат из DEV в промпте |
| NFR-06 | Безопасность | ключи и URL с `sig` только в `.env`; снапшоты наборов и звонки не в git |
| NFR-07 | Переносимость | Python 3.11, Windows и Linux, UTF-8, фронт без сборки |
| NFR-08 | Готовность к Dynamics 365 | компонент монтируется в `<div>`, параметры из query-строки, базовый URL API настраивается, CSS с префиксом `cqa-`, без глобальных библиотек |
| NFR-09 | Изменяемость | замена критерия ≤ 5 мин через UI; смена модели — `.env`; смена промпта — файл шаблона (см. карту изменений в `architecture/README.md`) |
| NFR-10 | Наблюдаемость | каждый вызов LLM в БД; прогон пишет сводку: время, стоимость, ошибки |
| NFR-11 | Языки | диалоги RU / KZ / EN; интерфейс на русском |
| NFR-12 | Качество интерфейса (Лида: «интерфейс должен быть очень хорошим») | единый стиль на CSS-переменных, понятные состояния (загрузка, пусто, ошибка, «требует проверки»), режим демо с крупным шрифтом для проектора, без горизонтальной прокрутки на 1280 px, клавиатура для частых действий; проверка Лидой на M3 и M5, проход по удобству (FR-UX-07) |
| NFR-13 | Обоснованность | 0 выдуманных цитат после проверки; у каждого «Нет» — место, у N/A — причина; при нехватке данных — пометка, а не догадка; выборочно 10 обоснований логичны и не противоречат ответу |
| NFR-14 | Воспроизводимость | повтор прогона с тем же конфигом меняет ≤ 5% ответов, итог в среднем ≤ 2 баллов; все параметры прогона сохранены |
