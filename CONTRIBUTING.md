# Как мы коммитим и мержим

Команда из двух человек и сутки на всё, поэтому правила простые.

## Авторство

- Все коммиты от `Adilm8 <adtsco00@gmail.com>` (автор и коммиттер).
- Никаких трейлеров `Co-Authored-By`, `Claude-Session` и строк «Generated with ...» в коммитах и описаниях PR. Упоминаний ассистента там тоже нет.
- Перед первым коммитом в новой среде:
  ```bash
  git config user.name Adilm8
  git config user.email adtsco00@gmail.com
  ```

## Ветки

- `main` всегда рабочий: тесты зелёные, сервер стартует. Напрямую в `main` не пушим.
- Одна задача = одна короткоживущая ветка от свежего `main`: `feat/<что>`, `fix/<что>`, `docs/<что>`, `eval/<что>`, `chore/<что>`.
- Если ветка зависит от другой незамерженной ветки, ответвляемся от неё и в PR указываем базу.
- Ветка живёт часы, не дни: мержим, как только задача закрыта и проверена.
- Одна задача = одна ветка = один PR. Никаких резервных и промежуточных копий веток (`backup/*`, `rewrite/*`): история и так есть в git.
- Ветки удаляет GitHub сам после мержа (Settings → General → «Automatically delete head branches»). Удалять ветки из облачной сессии нельзя: шлюз GitHub отвечает 403.

## Сообщения коммитов (Conventional Commits)

```
<тип>(<область>): <что сделано, в повелительном наклонении>

<зачем, если неочевидно; как проверено>
```

Типы: `feat`, `fix`, `docs`, `test`, `refactor`, `eval` (промпты, gold, прогоны), `chore` (конфиги, зависимости).
Области: `api`, `scoring`, `evaluator`, `llm`, `ui`, `data`, `eval`, `docs`.

Примеры: `feat(scoring): weighted total per checklist`, `eval(evaluator): tighten prompt for criterion 04`, `fix(ui): jump to quoted message`.

Коммиты маленькие и по одному смыслу. Секреты, `.env`, `data/raw/` не коммитим.

## Pull request и мерж

- PR в `main` на каждую ветку. В описании: что сделано, как проверено (команда и результат), открытые вопросы.
- Перед мержем: `pytest -q` зелёный; если менялись промпт или оценщик, приложить метрики `run_eval.py` до и после.
- Мерж только **squash merge**: в `main` один коммит на PR, заголовок коммита = заголовок PR в формате Conventional Commits.
- После мержа ветку удаляем. Остальные ветки подтягивают `main` через `git rebase origin/main`.
- `force-push` допустим только в свою незамерженную ветку (`--force-with-lease`). В `main` никогда.
