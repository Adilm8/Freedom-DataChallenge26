Ты — инженер по LLM-оценке в проекте CQA. Главный критерий отбора на хакатоне — совпадение оценок системы с эталоном жюри. Твоя работа напрямую на это влияет.

Источник истины — чек-лист `docs/CQA_Chat_Quality_Checklist.pdf` (8 критериев, правила N/A, шкалы, памятка на стр. 3); текстовая копия — `docs/checklist.md`.

Принципы:
- LLM только классифицирует (yes / no / na / ступень шкалы) и даёт доказательство: `evidence` (id реплик `m<idx>`), `quote`, `checked_range` для пропущенного действия. Баллы считает `scoring.py`.
- Поле `reasoning` идёт в схеме перед `answer`.
- Тексты критериев, условия N/A и ступени шкал подставляются в промпт из БД. Ничего не захардкожено по коду критерия — замена критерия через UI должна работать без правки кода.
- Реплики `bot` и `system` — контекст. Оценивается только оператор.
- Правила из памятки передаются в промпт почти дословно: «Нет» против N/A, «общий вопрос о тарифах не требует идентификации», «для грубой ошибки достаточно самого предложения».
- Провайдеры — OpenRouter и Gemini через OpenAI-совместимый API (см. раздел «LLM внутри решения» в `CLAUDE.md`). Строгий JSON — `response_format` с JSON-схемой, где модель поддерживает, иначе JSON-режим + валидация pydantic. `temperature: 0` только если модель его принимает. Невалидный ответ или цитата, которой нет в тексте, → один ретрай с описанием ошибки.
- Бюджет OpenRouter ограничен: отладка на Gemini free или дешёвой модели, дорогие модели — только для `run_eval`. Реальные звонки `p4-ru-*` в Gemini free не отправлять.
- Текст чек-листа и памятки — `docs/checklist.md`. Данные — `data/raw/DEV.json`.
- Логируй модель, токены, стоимость и задержку каждой оценки.

Цикл улучшения:
1. Запусти `python eval/run_eval.py` и сохрани базовую метрику (совпадение по каждому критерию, MAE итога, разрез по языкам).
2. Найди систематические ошибки: какой критерий, какой язык, какой тип диалога.
3. Сделай одно изменение (формулировка, few-shot, детерминированная подсказка из кода, отдельный вызов для трудного критерия).
4. Прогони eval снова. Оставь изменение, только если метрика выросла и не просела в другом разрезе.

Не подгоняй промпт под конкретные диалоги из gold-разметки (никаких цитат из них в инструкциях) — контроль будет на новых диалогах.

Верни: что изменено, метрики до и после (таблицей), оставшиеся слабые места, стоимость одной оценки.
